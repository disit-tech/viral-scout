# Dashboard

A Next.js app in `web/` that shows every business profile: outliers, fastest posts, rising posts and tracked links as cards (thumbnail, labels, metrics, growth sparkline, hook, transcript), plus the AI ideas notes, a swipe-file board and source health.

It runs in two modes:

| | Local (your PC) | Published (Vercel, free Hobby plan) |
|---|---|---|
| Start | `cd web && npm install && npm run dev` → http://localhost:3210 | `scripts/publish.ps1` |
| Data | `web/data/*.json`, refreshed after every run | a snapshot uploaded with each deploy |
| Save / Track / Dismiss / swipe status | run the Python CLI and update the vault | read-only; the buttons copy the CLI command |
| Login | none (unless `SITE_PASSWORD` is set) | password (`SITE_PASSWORD`); locked if it's missing |

Nothing runs in the cloud. Collection stays on your PC (home IP, yt-dlp, the scheduled task). Vercel only hosts the pages.

## Data flow

```
python -m viral_scout run <profile>      → data/<profile>-latest.json + SQLite
   └─ export (automatic after each run)  → web/data/<profile>.json, web/data/index.json
python -m viral_scout export [profiles]  → the same, by hand
scripts/publish.ps1                      → export + vercel deploy --prod (uploads web/ incl. data/)
```

`web/data/` is git-ignored, so the public repo never contains business data. The deploy uploads it straight from your PC: `web/.vercelignore` deliberately doesn't exclude it.

## Publish to Vercel

One-time setup:
```powershell
npx vercel login                       # once per PC
scripts/publish.ps1 -SetPassword       # links project "viral-scout", asks for a password, deploys
```

Afterwards:
```powershell
scripts/publish.ps1                    # export + production deploy
scripts/publish.ps1 -Preview           # preview URL instead
```

To publish automatically after the scheduled run, pass `-Publish` to `scripts/schedule.ps1`: it adds a `viral-scout publish` task after the last profile, on the same weekly day. Or add `pwsh -File scripts/publish.ps1` to your own task after `run-daily.ps1`.

**Free plan notes:**
- Vercel Hobby is meant for personal, non-commercial use. If the dashboard becomes a client deliverable, move it to Pro.
- Vercel's own "Password Protection" is a paid feature, so this app has its own login: an HMAC-signed cookie, valid 30 days. It runs in `src/proxy.ts`, Next 16's replacement for middleware.
- Every page is pre-rendered at build time. The only server code that runs is the login check, which fits comfortably in the free limits.

## Pages

- `/search` (**Search posts** in the nav; it creates nothing): searches titles, hooks, endings, transcripts and captions. Locally it covers the full history of every business through the Python CLI; the published site searches the latest runs in the browser.
- `/new` (**+ New business** and **Quick research** on the Businesses page): pick **New business** (an ongoing profile, reports go to an Obsidian project folder you pick) or **Quick research** (a one-off `research-…` profile, reports go to the repo's `reports/`; `/new?mode=research` opens it directly). Describe the business or topic and add search phrases. Hashtags, the topic filter and the spam rules are derived for you, and the first run starts in the background while the page shows its progress. Local only.
- `/p/<profile>/demand` (the **Search demand** tab): Google Trends for the profile's area. *In season now* (each service with its season and end date), *Next to prepare* (start posting by, demand rises, peak, ends), *Which words people use* (shares on one scale), and a card per term: now vs last year, vs normal and the 2-year trend, the average year by week with the seasons shaded and today marked (hover for the value, or switch to a table), the last 5 years, rising buyer searches, top related searches, other rising searches (often noise) and where in the area people search most. See [search-demand.md](search-demand.md).
- `/activity` (**Activity** in the nav, with a pulsing dot while something runs; local only): what is running on this PC right now. Every `run`, `ads` and `perf` command writes a live log to `data/activity/` (also the progress lines `--quiet` hides), whoever started it: the CLI, the weekly task, an AI agent or the dashboard. Per run: status, elapsed time, time since the last output, a progress bar for ads runs (searches done of planned, per source: Facebook/Instagram, TikTok, Google), the ads found so far and the live log (follow mode). Above it, Apify: spend this cycle against the plan limit, the cap per run, and every actor run of the last 6 hours with its status, duration and cost, linked to the Apify console. Refreshes every 3 s; reading Apify's run list is free. CLI: `python -m viral_scout activity`.
- `/setup`: every API key with what it unlocks, its cost, how to get it and a docs link. Paste, **Save** and **Test** it. Keys go into `.env` on your PC through stdin (never on the command line). Secrets are always shown masked. Actor ids and settings are shown in full. Local only; the published site never manages keys. The **Ads: Apify actors** group names the actor each route is built for, and **Spend controls** holds `APIFY_MAX_USD_PER_RUN` (the cap per Apify run) and `VIRAL_SCOUT_MCP_PAID` (whether MCP clients may start paid runs). **Test** on an actor only looks it up, so nothing runs or bills. **Test** on `APIFY_TOKEN` shows the plan and this cycle's spend against its limit (for example `$3.35 of $19 used this cycle (resets 2026-12-13)`), and fails once the limit is reached, because then every Apify run is blocked.

- `/p/<profile>/performance`: **Your performance**. Your own videos and ads: KPI cards grouped A–E (hover for formula and denominator), an organic / paid toggle, the 5 tests per video, a retention curve with drop-off markers, the diagnosis, priorities, unit economics and CSV import steps. Read-only; data from `web/data/perf/<profile>.json`. See [performance.md](performance.md).
- `/`: one card per business, with posts, outliers, 🔥 mega, saved, and the top thumbnails.
- `/p/<profile>`: the **business overview**. Every business page shares a tab bar: **Overview · Videos · Ads · Search demand · Ideas & swipe file · Runs · Your performance · ⚙ Settings**. The overview shows the description (with **Edit business**), **This week** (what's in season, the next "start posting by" date, new 3×+ videos, ads worth studying, saved ideas still to film, budget warnings), and one card per section with its status (up to date / older than a week / not run / not set up), last run, key numbers, a preview and a Settings link. Free jobs have a **Run now** button on the local dashboard: **Run YouTube now** (`run <profile> --free`: YouTube, watch list and re-checks, skipping TikTok on Apify) and **Re-score last run** for ads (`ads <profile> --rescore`, fetches nothing). Paid runs (Apify ads, TikTok, search demand) stay on the Monday schedule.
- `/p/<profile>/videos`: every post of the business on one board, no sub-tabs. **Show** picks the view: **All posts**, **Outliers** (3×+ the creator's usual; posts with no creator baseline can't be outliers), **Fastest** (search finds by views per day), **Rising now** (growth since the previous run), **Tracked**, **Your posts**. Each view is computed from all posts, not a top-25 list, and ranked its own way (sort "best first"). Then the same tools as the ads page: cards, a sortable **Table** or **Groups** (creator, platform, search, outlier tier, post age, posted month, first-seen day, last-scanned day, length, creator size); filters for search, platform, × usual tier, minimum views, posted within, first seen within, creator, search, new, hide saved, emerging creators, has a hook. The platform chips list every platform the business has, with the count in the current view; an empty one is greyed out with the reason. A collapsible creators table follows the filters. 14 sorts, CSV export, everything in the URL (`?show=rising` …; old `?tab=` links still work). Every card shows when it was last scanned and first seen.
- `/p/<profile>/runs` (the **Runs** tab; was Sources under Videos): one section per run, videos, ads and search demand, each with when it ran, what it kept, errors and what it used (YouTube API units, page loads, Apify results, transcription time). What didn't run is listed with a plain tag: *expected* (e.g. TikTok in a free run), *temporary* (rate limits, retried next run), *key added since* (the key is set now, so the next run includes it), *optional* (EU-only ad libraries) or *needs a key* (with a Setup link), plus the original message. For videos also: hashtags that keep appearing on found posts but aren't in the search list, each with a ＋ that adds it to the profile (local); creators who keep showing up, as watch-list candidates; recent runs. The Ads page keeps a short "This ads run" panel that links here; the old `videos?tab=health` link redirects here.
- `/p/<profile>/swipe` (the **Ideas & swipe file** tab): the swipe file, saved videos and competitor ads on one board with idea → scripted → filmed → posted → skip columns, filterable by videos or ads. Changing a card's status locally edits the note's `status:` in the vault. Saved ads open the ad page. Below it, the **Idea notes**: the `<date>-viral-ideas.md` notes written by the `/viral-scout` skill, rendered as HTML (`#ideas`). The old `videos?tab=swipe` and `videos?tab=ideas` links redirect here.
- `/p/<profile>/settings` (local only): edit the profile without touching YAML. **Business** (display name, description, report folders), **Videos** (YouTube/TikTok keywords and hashtags, watch lists, tracked links, your channels, filters), **Ads** (competitors with an optional name pattern, keyword searches, domains, countries, topic words, excluded advertisers, look-back), **Search demand** (terms, wordings to compare, area, refresh, lead time), **Local & your performance**. Fields that cost Apify credits are marked *paid*. Each section saves on its own through `python -m viral_scout profile <name> set`, which edits only the changed values in `profiles/<name>.yaml`: comments, line endings and everything else stay as they are. The new file must read back as exactly the requested change or nothing is written; the old file goes to `data/profile-backups/` first; a save is refused if the file changed since the page loaded. The profile ID (file name, vault folder, links) can't be renamed here; the display name is what the dashboard shows.
- `/p/<profile>/ads` (the **Ads** tab): the ads scout ([ads-scout.md](ads-scout.md)). Three views: **Cards**, a **Table** (click a column header to sort, click a row for the full copy, where it was found and the library link) and **Groups** (group by advertiser, platform, placement, offer, format, CTA, landing domain, the search that found it, running time, start month or label; each group shows its ads, running count, 30d+ count, longest run and best score, and expands to its top ads). Filters: platform chips (Facebook/Instagram, Google, TikTok) with counts, running or stopped, minimum days running (7/30/60/90+), competitor searches vs keyword/category searches, new since the last run, format, offer, advertiser and text search. The advertiser table follows the filters, sorts by any column, has a search box, lists the platforms each advertiser runs on, and **hide** removes an advertiser from the view (for example Angi's ads that recruit contractors). Filters, view and sort live in the URL, so a link reopens the same view. **CSV** downloads what's shown. Cards load 60 at a time. Below: offers that keep running (click one to filter), coverage (including what the noise filter dropped), skipped sources and lookup links. Read-only, from `web/data/ads/<profile>.json`, which `python -m viral_scout ads|export` writes. Meta snapshot URLs, which carry the access token, are never exported.
- `/p/<profile>/a/<ad>`: **one ad in detail** (click any ad card, table row or group card). The creative (image, video while the signed link lasts, or a text ad laid out as in search results). **Why it's worth studying**: days running against the 21/30/60/90-day marks, compared with the advertiser's median run, variants, score rank, new this week, and whether a competitor or keyword search found it. **Numbers**. **Copy breakdown**: the part people see before "See more" (about 125 characters on Facebook/Instagram, 90 for a Google description) in bold, the hook and whether it fits, the problem it names, offer, money/free, proof (reviews, years, warranty, licence), urgency, CTA, voice and length. **Variants**: the other versions in the same group. **The advertiser's playbook**: their ads in this run on a start→stop timeline (hover a bar, click to open it, or switch to a table), median and longest run, offer, platform and format mix. **Same angle elsewhere**: other advertisers with overlapping copy or the same offer. **History**: first and last time viral-scout saw it. Links to the ad library, the landing page and the lookup pages. All of that is computed from the collected data, with no AI and no extra cost. On the local dashboard the page also has three buttons: **Transcribe video** (local Whisper, free), **Run AI breakdown** (Claude Code CLI headless on your subscription, about a minute: scorecard on 8 criteria, how the ad is built, risks, **our version** with a must-be-true checklist, test ideas) and **Save to swipe file** (a note in the vault, with a link that opens it in Obsidian). Each run shows on the Activity page. The results are exported, so the published site shows them read-only. See [ads-scout.md](ads-scout.md#one-ad-in-depth-transcript-ai-breakdown-swipe-note). A **★ worth studying** badge marks the ads to open first: the best-scoring ads that ran 21+ days or have 3+ variants, at most 3 per advertiser and one per variant group, about 10% of the ads (a fixed day threshold marked most of them, because competitors' evergreen ads clear any bar), with a filter for it on the ads page.

## Security

- Local actions only accept requests whose host is `localhost` or `127.0.0.1`. The Python CLI is called with fixed arguments, never through a shell.
- On Vercel (`VERCEL` is set) actions are switched off, and the API answers 403.
- Pages send `X-Robots-Tag: noindex` and set `robots: noindex`.
